# Changelog

Each entry states **Regeneration required** — whether project context generated by an
earlier version must be re-applied after updating the skill. Since v0.5.0 the validator
enforces this by `(major, minor)` of the recorded skill version: a patch delta is a visible
warning, a minor/major delta reports `context_state: invalid` until the audit is re-run.
Before v0.5.0 the check was strict: any version delta invalidated the context.

## v0.5.0

**Regeneration required: yes** (the version-skew policy itself changed, and new preflight
fields feed generation).

- Version skew: only a `(major, minor)` mismatch between the manifest and the installed
  skill invalidates a context; patch deltas warn in `validate-project` and the dashboard.
- Preflight reports host-file problems (symlinked or non-UTF-8 `CLAUDE.md`/`AGENTS.md`,
  malformed managed markers, symlinks under `repodocs/`) structurally in `host_errors`
  instead of crashing — the dashboard now starts and shows the invalid state.
- The agent-instruction map also discovers git-ignored instruction files (bounded to
  instruction basenames) and marks them `ignored`; NTFS junctions are treated as symlinks
  by every containment guard; the full test suite runs on Windows CI.
- `validate-findings --previous-sha256` verifies the prior findings file against the last
  valid manifest hash before its ids and refuted history are inherited.
- Machine-read label shapes (`## ADR-NNN:` / `## MB-NNN:` headings, `Priority:` / `Effort:` /
  `Status:`) are documented as literal in any language, with a validator tripwire for
  anchors without their heading; the drift-report template records blind-pass depth.
- `audit_agent_config` folds stale-symbol/dead-file rows into the instruction map
  (direct-read confirmed, redundancy output dropped); executable eval subset with fixture
  builders and a scorecard; `RELEASING.md` documents the release ritual incl. dogfood run;
  the CI installer job exercises a real cross-version update and the legacy-archive path.
